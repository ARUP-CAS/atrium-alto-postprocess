## Context

The issue was opened as a 2010+ categorisation complaint. The cause was `rule_short_garbage` (gate 6 of `determine_category`, `text_util.py:1353-1371`), which returned `Trash` unconditionally for any 1–3 token line without Czech diacritics, weak language ID and any weirdness. It was the largest single `Trash` producer — 6,333 firings, 28.4% of all `Trash` lines — and it fires hardest on post-2000 documents because those are tabular, one value per cell.

@david-spacil proposed gating it behind `_has_strong_garbage_evidence()`, the same predicate six §9 rules use. That change is now merged. Measured over both collections recomputed twice on the same base, it moves **367,208 lines and demotes none** — `Trash`→`Clear` 153,353, `Noisy`→`Clear` 119,956, `Trash`→`Noisy` 93,899 — dropping `Trash` by 247,252 lines (−8.68%) across 113,101 documents and 71,815,774 lines, with `Non-text` and `Empty` untouched. 484 of the promoted lines scored blind by a human annotator (0 = right, 1 = borderline, 2 = wrong; key held aside on shuffled samples), design-weighted with decade strata, give **76.5% right / 9.6% borderline / 13.9% wrong** — a 5.5 : 1 ratio, and roughly **26,000 garbage lines reaching `Clear`**, the top category rather than a reviewable middle state. `tools/SWEEP_NOTES.md` classifies the rule `LOAD-BEARING`.

Two framings were tried and abandoned before the change was taken on its measurements. The **symmetry argument** (that the rule is the seventh sibling of six gated rules) does not hold: `50472fb` added `qs < thresh_trash` to sites that were already gated and never touched this rule, which sits among eight *early-exit* rules that all return unconditionally. And **"367,208 lifted / 0 demoted"** is a theorem rather than a measurement — deleting an unconditional `return Trash` is monotone by construction — so the only evidence about whether the change is *right* is the graded sample.

## Research

**1. What separates the two populations at 1–2 tokens.**
*Superseded in part by §5.* Of the signals the pipeline **passes to `determine_category`**, nothing separates them: `vansasaasasa` and `malakofauna` agree on valid-word ratio (1.000), weird ratio (0.350), garbage density (0.000), gibberish (0), ghost share (0) and raw quality score (0.647 vs 0.647). A quality-score gate was built and measured: dead, because raw pre-alignment scores overlap completely (garbage 0.52–0.65, notation 0.49–0.86, with `II/C` and `I-VIII-c` *below* most garbage). §5 shows that a signal the pipeline **computes but does not act on** does separate much of it.

**2. Whether perplexity can arbitrate.**
No, and it runs backwards. Both surviving routes gate on *low* language-ID confidence; FastText scores `oueussd` at 0.9163 and `malakofauna` at 0.56. With the cap lifted, real notation demotes at perplexity 3,000 while `oueussd` survives to 30,000. Recomputed values corroborate: `II/C` ≈ 6·10⁷ (correct) against `oueussd` ≈ 4,600 (garbage). Independently: because `SHORT_PPL_CAP` (850) < `HARD_SWEEP_PPL_MIN` (1,000) < `PPL_EXTREME_MIN` (3,000) < `PPL_GARBAGE_ABSOLUTE` (30,000), **no perplexity rule can fire at all on a 1–2 token line**. Four cap variants were then measured end to end and none is separable from the patch — see the accuracy ledger in [`../digests/30.digest.md`](../digests/30.digest.md) §3.5.

**3. Whether the existing structural protections could be widened.**
`is_structured_line()` (`text_util.py:2155`) dispatches to seven predicates; all seven returned `False` on all 35 thread examples (245 evaluations, zero matches). But widening *that* predicate is the wrong lever — it is read at eleven places and is an absolute veto at the first statement of `_has_strong_garbage_evidence()` (`text_util.py:1672`), so widening it would also disable `rule_allcaps`, `rule_garbage_density`, `rule_zero_alpha`, `rule_vowelless` and `rule_mid_uppercase`. Hence a separate, narrower predicate.

**4. Whether the wc/char boundary can isolate the problem lines.**
No, and this was asked directly in the thread. Error rates are flat — 31% / 28% / 25% by token count, 17–42% by character band with no monotone trend — and the tightest `wc <= 3, chars <= 24` box encloses 482 of 508 lines, 343 of them correct. `sektlll` and `edelite` (wrong) sit in the same band as `Kaaden` and `Pinii` (right). **That is why the narrowing is a shape predicate and not a boundary.**

**5. The pipeline already computes a discriminating signal, and the short-line path throws it away.**
This is the finding that unblocked the plan, and it falsifies the claim that stood for three rounds — carried by `tests/test_text_utils.py`, by `is_domain_notation()`'s own docstring, and by PR #48's *Known limitation* section — that no character-level rule separates `oueussd` from `malakofauna`.

`detect_fused_words()` (`text_util.py:773`), built on `_RE_FUSED_VOWEL_RUN` (`text_util.py:770`, 3+ vowel run) and `_RE_FUSED_CONSONANT_RUN` (`text_util.py:769`, 5+ consonant run), returns **1** for `oueussd`, `sektlll`, `cuxoaid`, `Tthts I` and **0** for `malakofauna`, `diapozitiv`, `Occipitale`, `Equus caballus`, `Kaaden`, `Pinii`, `kontext`, `Uniocrassus`, `Ossa tarsi`, `radius prox.sin.`, `1 ks`, `II/C`.

Section 7 (`rule_short_line`) **already reads it**, inside its `damage` term:

```python
or ((gibberish_present or detect_fused_words(text_source) > 0) and not structurally_clean)
```

with `structurally_clean = valid_word_ratio >= 1.0`. But `valid_word_ratio` is a **shape-only** heuristic — `compute_valid_ratio()` (`text_util.py:2405`) counts a token valid on length ≥ 3, ≥ 70% alphabetic, no strange character, no mid-word uppercase — so it is **1.0 for every line in this population**, `oueussd` included. The one witness that discriminates is suppressed by the one signal that cannot. The limitation was a **suppression bug in the short-line path**, not an absence of signal.

**6. On this population the merged gate is equivalent to deleting the rule.**
`_has_strong_garbage_evidence()` returned **False on 16 of 16** disputed lines. With `valid_word_ratio` 1.0, `weird_ratio ≈ 0.35`, gibberish 0 and density 0.0, its only live clause is `lang_score <= 0.20 and orig_lang_score <= 0.50` — i.e. `orig_lang <= 0.40` after `TRUST_TIER_UNKNOWN` (0.50) scales it; the last conjunct misses by 0.05 (`weird_ratio >= 0.40` against 0.35). `thresh_trash = CATEG_TRASH_SCORE_MAX + 0.35 = 0.90` is nearly always true, so the predicate is the whole gate. Measured through the real `determine_category`:

| variant                         | real vocabulary → `Trash`     | garbage → not-`Trash`                |
|---------------------------------|-------------------------------|--------------------------------------|
| baseline (pre-merge)            | 8 / 9 — the issue's complaint | 0 / 7                                |
| + the evidence gate (merged)    | 0 / 9                         | **7 / 7, all reaching `Clear`**      |
| + shape witness at gate 6 (D15) | 0 / 9                         | flags 9 / 9 of the reachable garbage |

So "require a second witness" is, on this population, a **suspension** of the rule rather than a narrowing: there is no second witness to consult, and the rule simply stops convicting. Pinned in-tree on production vectors by `tests/test_calibration.py::test_strong_evidence_is_false_on_the_entire_disputed_population`.

Corollaries that constrain any fix:

- **For `wc <= 2` the promotion happens in section 7, not gate 6.** `rule_short_line` (`text_util.py:1380-1439`) always returns, so nothing below it — including all six §9 gates and the §10 band routing — is reachable for 1–2 token lines. Its final branch returns `Clear` when `valid_word_ratio >= 1.0`.
- **`wc == 3` is a different regime.** `SHORT_PPL_CAP` covers `wc <= 2` only, so 3-token lines already reach the perplexity routes with raw perplexity, `damaged` becomes live, and §8–§10 are reachable. That, not "shorter is riskier" as a law, explains the 3.6 / 5.1 / 6.8 : 1 gradient in the grading — consistent with §4's flat error rates once borderline lines are included.
- **`check_rescues()` (`text_util.py:1462`) cannot supply the `Noisy` floor.** All three of its floors — `_trailing_fill_rescued()`, `is_forgiven_headline()`, `is_clean_reference()` — evaluate `False` on all 11 lines tested, so it returns `Trash` for every one, `malakofauna` and `1 ks` included. Routing gate 6 through it makes the symmetry argument literally true and changes **nothing** on the disputed population.

**7. The corrected witness, and what it costs to get it right.**
`_has_shape_garbage_evidence()` (`text_util.py:1770`) is a vowel-run test, an initial-consonant-geminate test, a triple-character test and a character-variety test, applied only to alphabetic sub-tokens of length ≥ `SHORT_GARBAGE_WITNESS_MIN_ALPHA` (4) not in `_NEUTRAL_LEXICON` / `SHORT_EXCEPTION_TOKENS` / `SHORT_VALID_WORDS`, and vetoed by `has_cz_diacs()` / `is_structured_line()` / `is_domain_notation()`.

Re-measured directly for this revision (pure text function, no scoring stack needed):

| set                                              | n  | flagged                                                                                                                                                           |
|--------------------------------------------------|----|-------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| thread garbage, reachable                        | 9  | **9** — `oueussd`, `cuxoaid`, `IDIDIDIDIDIDUOID`, `nnnooo` (vowel run), `sektlll`, `NINNNIC` (triple), `Tthts I`, `rragment` (geminate), `vansasaasasa` (variety) |
| vocabulary + notation + toponyms + names + units | 37 | **0** — incl. the whole `vrstva` family, `Skelettmaterial`, `Aachen`, `Schifffahrt`, `malakofauna`, `II/C`, `1 ks`, `mm`                                          |
| phonotactically legal residue                    | 6  | **0** — `edelite`, `vfetennl k.`, `Slaot-o hiezazzt`, by construction                                                                                             |
| known loan false-positive class                  | 7  | **5** — `Poaceae`, `Naiade`, `Beaune`, `Radiouhlik`, `Sauerstoffflasche`                                                                                          |
| every committed positive fixture row             | 37 | **0**                                                                                                                                                             |

Against exactly the lines printed in the §7 grading tables: **8 of 15** labelled *wrongly lifted* flagged, **0 of 25** *correctly lifted*, **0 of 4** borderline.

**These are the lines the thread happened to print, not a random sample.** It is a feasibility signal. If that recall held on the real changed population the wrong-lift share would fall from 13.9% toward 6–7% at no cost to the correct lifts — that must be measured on the 508 before it is claimed.

**8. What earlier revisions of this document got wrong.**
Both errors were the kind that pass review, neither was visible from reading the code, and both took running it. Recorded because the failure mode recurs, not to relitigate:

- **Placement.** An earlier revision put the witness in section 7's `damage` term and recorded that landing it there would turn D8's strict xfail into `XPASS(strict)`. It does not: section 7's `damage` branch returns `Noisy` (`text_util.py:1424-1425`) and the test asserts `== "Trash"`, so the test would have stayed `xfail` forever while the visible improvement (`Clear` → `Noisy`) was mistaken for the debt being paid. Traced on a patched module: `oueussd` and `sektlll` both go `Trash` → `Clear` (gate) → `Noisy` (gate + section-7 fix).
- **Signal.** An earlier revision specified a "run-only form of `detect_fused_words`". That is **two** regexes, and `_RE_FUSED_CONSONANT_RUN` (5+ consonants) matches `vrstva`, `vrstvy`, `vrstvou`, `vrstvami`, `ctvrtek`, `ctvrt`, `zmrzl`, `scvrkl` — ordinary diacritic-free Czech. `vrstva` ("layer") is the commonest noun in archaeological field documentation, and `vrstva 3` satisfies every condition of gate 6 at production signals, so a witness carrying that clause would `Trash` it: a demotion of clean text, the one outcome this thread exists to prevent. **Only the vowel run is safe**, and nothing is lost — `sektlll` is reached by the triple test and `Tthts I` by the geminate test. The geminate test also had to be narrowed to consonants (a bare `^(.)\1` takes `Aachen`) and the triple test length-capped (an uncapped one takes `Schifffahrt`).

## Algorithm sketch — where a short line is decided now

1. **Section 1** — three perplexity routes. Notation is exempt from `rule_extreme_ppl` and `rule_absolute_ppl`; `rule_hard_sweep` still applies when FastText independently failed to place the line. At `wc <= 2` none of the three can fire at all, because `SHORT_PPL_CAP` (850) sits below every threshold.
2. **Sections 2–4** — inverted scan, all-caps, garbage density. Unchanged. Notation is not immune here: `Reg.Bez.Aussig.` sits at `rot_ratio` 0.583 against a 0.65 threshold, `II/C` at `garbage_density` 0.25 against 0.35.
3. **Gate 6 `rule_short_garbage`** (`text_util.py:1353-1371`) — skipped when `forgiven`, `structured`, or `is_domain_notation()`. **Now gated**: it fires (`_fire` is recorded above the gate, so telemetry still sees exposure) but returns `Trash` only when `qs < thresh_trash` **and** `_has_strong_garbage_evidence()`. On the disputed population that predicate is `False` throughout, so the rule convicts none of it (§6). **This is the only site in this path that returns `Trash`, and therefore the only place the witness can go.**
4. **Gate 7 `rule_short_line`** (`text_util.py:1380-1439`) — total for `wc <= 2`; every branch returns, so §8–§10 and `check_rescues()` are unreachable for that population. Its `damage` term already reads the discriminating witness and discards it via `structurally_clean` (§5); its `damage` branch returns `Noisy`, never `Trash`; its final branch returns `Clear` on `valid_word_ratio >= 1.0`, with `categorize_line` clamping the stored score *up* to `CATEG_NOISY_SCORE_MAX` (0.80) — `II/C` goes from a raw 0.4792 to a pinned 0.80.

Step 4 is where D11 would have belonged, and it is where the measurement killed it. **D15 belongs at step 3** — that was the error corrected in §8: step 4 cannot return `Trash`, so a witness placed there converts "garbage reaches `Clear`" into "garbage reaches `Noisy`" without ever restoring a `Trash` verdict, and the strict xfail that tracks the debt never flips.

## A decision-quality checklist for this class of change

Derived from what actually went wrong in this thread, and worth applying to D15 before it ships:

1. **Is the headline metric monotone by construction?** "367,208 lifted / 0 demoted" was — removing an unconditional `return Trash` cannot demote anything. A direction that was never in question is not evidence.
2. **Does the harness compute what production computes?** Three harnesses in this repo have fed `categorize_line` a value the pipeline never produces. All three are fixed; the fourth is the one to watch for.
3. **Can the test suite see the change?** The old golden `short_garbage` case was set up so that the gate under review could not alter its outcome.
4. **Does the new feature reach a rule?** `apply_page_perplexity_blend()` and `rule_domain_notation` both shipped in `8fadeb9` unable to change any outcome, for two different reasons. `_has_shape_garbage_evidence()` is the third, deliberately — and D15 is what ends that.
5. **Is the analogy load-bearing or decorative?** The "seventh sibling of six gated rules" symmetry did not survive reading `50472fb`'s diff.
6. **Is the signal absent, or present and discarded?** Research §5 is the case in point — three rounds concluded a lexicon was required while the discriminating witness sat two lines above the conjunct that suppressed it.
7. 🆕 **Did you run it, or read it?** Both errors in §8 passed code review and failed on execution. Neither was visible from reading.

### The gold set is inverted relative to the population

Decade parses from the document identifier. The sample is stratified, and its
strata are the opposite of the corpus's:

|                 | % of changed population | % of gold sample |              |
|-----------------|-------------------------|------------------|--------------|
| 1920s           | 0.1%                    | 5.4%             | **95x over** |
| 2010s           | 42.5%                   | 4.5%             | **0.1x**     |
| **2010s+2020s** | **55.5%**               | **9.3%**         | **6x under** |

Unweighted agreement over the 484 in-population gold rows is **62.8%**;
reweighted by decade population, **72.7%**. A ten-point swing from composition
alone, and `_metrics_from_labels` applied no sampling weight at all — the
`weighted_f1` it reports is weighted by *class support* and will be misread.

**The documents this issue is about are the thinnest-covered part of its own gold
set.** Pooling compounds it: 1,559 of the 2,067 rows are `calibration_1567`
lines the patch never moves, so 75% of a pooled objective comes from outside the
population being tuned.

Fixed: the gold report now always prints the breakdown by `gold_source` and by
decade beside the headline, warns when agreement varies by ≥10 points across
strata, and accepts an optional `gold_weight` column threaded as `sample_weight`
through every metric. **Weighting stays opt-in** — the design weights are the
annotator's, and inventing them here would be worse than reporting honestly that
the number is unweighted.

### The recategorization CLI was not shaped for 113k documents

`main()` globbed `*.csv` non-recursively with no `--recursive` flag (a
two-archive layout silently processed nothing and reported success) and defaulted
to **in-place overwrite**, destroying the baseline the run is measured against.
Now: `--recursive` with the output tree mirrored so same-named documents in
different archives cannot collide; `--out` or an explicit `--in-place` required;
per-file `try/except` so one malformed CSV cannot end a multi-hour run, with a
failed-file list and a non-zero exit; per-file progress; and an atomic
temp-then-rename write so a kill mid-write cannot leave a truncated CSV.

### The config path was resolved against the working directory

`text_util.py` and `classify_TEXT.py` both defaulted to the *relative*
`setup/config.txt`, so a process started anywhere but the repo root ran on
in-code defaults — `text_util` after one stderr line, `classify_TEXT` in total
silence — while `tools/recategorize_from_csv.py` resolved the same file
absolutely. One process, two configurations.

Measured: **0 of 84 scalar constants differ today**, so this was latent. That is
the argument for fixing it now rather than later — this round of runs exists to
*change* those constants, and the bug goes live the moment `setup/config.txt`
stops mirroring the defaults. Both are now anchored to their own module.

### `override_constants()` did not rebuild derived constants (2026-09-19)

The same class of bug as the config-path fix above, found while chasing 07c's
"zero effect on gold" result rather than latent and waiting. `_STRIP_CHARS`
(D27) is DERIVED from `STRIP_SYMBOL_GLYPHS` — built once, at import time, by
`if STRIP_SYMBOL_GLYPHS: _STRIP_CHARS = _STRIP_CHARS + _SYMBOL_GLYPHS` — the
same way `ROT_GHOSTLIST` and `_LANG_DIACRITICS` are already documented as
built once and *not* rebuilt by `override_constants()`. Those two are a known,
accepted limitation; `_STRIP_CHARS` was the same limitation, just never
recognised as an instance of it. `override_constants()` only `setattr`s the
names it is given, so a test or an A/B run that overrides `STRIP_SYMBOL_GLYPHS`
alone moves the flag and nothing downstream: `_STRIP_CHARS` keeps whatever it
was built with at import, and every `.strip(_STRIP_CHARS)` call site — 28 of
them — never sees the difference.

Verified directly against this repository: overriding `STRIP_SYMBOL_GLYPHS`
to `True` left `♦` out of `_STRIP_CHARS` on every check. This is why 07c
measured `STRIP_SYMBOL_GLYPHS` true vs false as bit-identical on all 2,064
gold rows — not a population-coverage gap, as first written up, but the A/B
harness never arming the flag it claimed to be testing.

**Fixed.** `override_constants()` now takes a small `_DERIVED_FROM_FLAG`
mapping (`{"STRIP_SYMBOL_GLYPHS": "_STRIP_CHARS"}`) and rebuilds — and
restores — the derived value in the same pass as the flag, generalising
cleanly if a future flag needs the same treatment. A regression test,
`test_symbol_glyph_stripping_actually_arms_under_override`, exercises the
override path specifically — the existing `test_symbol_glyph_stripping_ships_off`
only ever checked the flag at its shipped default, which is exactly the gap
that let this hide. Both pass, and the full suite (`pytest tests/`, minus the
two service-API modules this sandbox has no `fastapi`/`jsonschema`-free path
to) is otherwise green.

**07c is void, not zero.** The reported "zero effect on gold" result must be
re-run now that the flag actually reaches tokenisation; D27's status is
updated to reflect that above.
