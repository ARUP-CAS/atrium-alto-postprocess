# 🧭 Plan — Issue #30: Algorithm change for 2010+ years documents

> Issue [#30](https://github.com/ufal/atrium-alto-postprocess/issues/30) · Labels: `development`, `enhancement`, `integration` · **Status**: still open on GitHub. PR #32 addressed the literal verification request, but its own follow-up commits (`b50c1f3` → `6486c72` → `641f936`) surfaced a regex defect and an architecture question, both now covered by a 4-item action plan — 2 items already satisfied in code, 2 fixed and reviewed but not yet merged.

## Context

This issue is not a broad product spec. It is a check that the categorisation algorithm used for the corpus stays aligned with the real pipeline, using `tools/recategorize_from_csv.py` as the verification path. The PR author clarified that 2010+ was the highest-priority slice for Dana, not the only intended target, so the scope should be read as corpus-wide with a special focus on that subset.

PR #32 is the main implementation event. It merged into `test` on 2026-07-26 and introduced a cluster of related changes in `text_util.py`, including neutral-token handling, a structural short-line gate, damaged-token capping, a clean-reference floor, and extra fragment/bigram/case-mix rules.

That merge did not close the loop. A dense same-day/next-day review cycle (Sonnet, GPT, Gemini, and Claude Opus, across several accounts and sessions) treated `f6adc23` as a checkpoint: it root-caused the remaining test failures, then audited the follow-up commits (`b50c1f3` → `6486c72` → `641f936`) closely enough to catch two things a plain pass/fail test run wouldn't have — a real regex boundary bug in the measurement predicates, and an unresolved question about whether the six structural override rules should be cumulative score penalties or explicit named gates. Both are now addressed: the gates-vs-penalties question resolved itself in `641f936` (gates won), and the regex bug plus a stripped docstring were fixed in a follow-up review pass, delivered as a reviewed local patch not yet committed to the branch.
