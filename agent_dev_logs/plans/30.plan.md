## Context

This issue is not a broad product spec. It is a check that the categorisation algorithm used for the corpus stays aligned with the real pipeline, using `tools/recategorize_from_csv.py` as the verification path. The PR author clarified that 2010+ was the highest-priority slice for Dana, not the only intended target, so the scope should be read as corpus-wide with a special focus on that subset.

PR #32 is the main implementation event. It merged into `test` on 2026-07-26 and introduced a cluster of related changes in `text_util.py`, including neutral-token handling, a structural short-line gate, damaged-token capping, a clean-reference floor, and extra fragment/bigram/case-mix rules.

The current `test` branch docs describe the pipeline as a layered scorer with late penalty gates, rescue paths, score clamping, and document-level postprocessing that is shared with the offline re-scorer. That is a stronger and more complex system than the issue title alone suggests, so the plan should separate “issue ask” from “policy choices.”
