# Strategy — Issue #37: JSON-2-TXT breaks downstream architectural contract

> Issue [#37](https://github.com/ufal/atrium-alto-postprocess/issues/37) · Labels: `development`, `integration`, `bug`
> **Status: 🟡 PLANNED — design only, no production code touched yet**

## Context

Issue #37 addresses a critical integration gap introduced in `v1.2.1-beta`. The draft JSON-2-TXT extractor successfully generalizes plain-text extraction but outputs isolated raw text files. However, the ecosystem (specifically downstream tools like `atrium-llm-enrich`) converged on July 31st around the `atrium_document.schema.json` standard.

The extractor must be refactored to conform to the **paradata-pair accretion model**. This means the script is no longer a simple text dumper; it must accept a `doc.json` file, insert/merge extracted text into designated schema blocks, and output an updated `doc.json` while leaving unrelated metadata untouched. Additionally, a `--force-single-page` flag must be implemented to collapse segmented JSON structures into a single page.

## Research: Accretion Semantics and State Preservation

We audited the current requirements against the canonical `atrium_document` schema and downstream consumer expectations:

**1. The Accretion Contract:**
The extractor is only authorized to touch specific text blocks. The formula is: `input document + new extraction result = updated document`. Rebuilding the document from scratch is forbidden as it risks dropping unmapped fields.

**2. The Byte-Identical Constraint:**
The issue explicitly mandates that "untouched parameters from the input JSON remain byte-identical." Standard Python `json` parsing alters formatting. We must resolve whether this means literal byte-for-byte serialization preservation (requiring a specialized JSON library) or strict semantic preservation (`json.loads(input)["metadata"] == json.loads(output)["metadata"]`).

**3. Page Assembly:**
`--force-single-page` needs to be deterministic. If a document has multiple pages or segmented structures, this flag must concatenate the text sequentially without data loss or duplication, outputting exactly one page object within the updated `doc.json`.

## Design decisions

| #  | Decision                    | Recommendation                                                                                                                                                                                     | Rationale                                                                                                                                                                                                |
|----|-----------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| D1 | Architecture Split          | Decouple `extract_JSON_2_TXT.py` into two distinct layers: an **Extraction layer** (JSON source → text blocks) and a **Mutation/Accretion layer** (`doc.json` + text blocks → updated `doc.json`). | Prevents tangling file I/O with text parsing. Creates testable boundaries for extraction correctness vs. document preservation correctness. Sets up an easier path for #31 (Adaptation to other inputs). |
| D2 | Ownership Boundaries        | Explicitly map and document the exact JSON paths inside `atrium_document` that this script is allowed to mutate.                                                                                   | Prevents accidental overwriting of paradata, provenance tags, and unrelated upstream metadata.                                                                                                           |
| D3 | Data Preservation           | Enforce a strict `output[non_owned] == input[non_owned]` invariant. Address the "byte-identical" requirement via format-preserving JSON libraries or strict semantic validation fixtures.          | Directly satisfies the acceptance criteria and prevents breaking the `atrium-llm-enrich` contract.                                                                                                       |
| D4 | `--force-single-page` Logic | Implement this flag at the document assembly layer. Default behavior preserves source segments; the flag triggers deterministic concatenation into a single page object.                           | Keeps extraction logic format-agnostic. Ensures the flag can handle multi-page, heavily segmented, or already-single-page inputs gracefully.                                                             |
| D5 | Schema Validation Loop      | Integrate the canonical `atrium_document.schema.json` directly into the test suite/development loop as an active fixture.                                                                          | Schema conformance is an acceptance criterion. Validating at every step prevents pushing a semantically correct but schema-invalid document.                                                             |

## Algorithm sketch for Accretion

1. Load existing `doc.json`.
2. Locate document/page/text structures defined by `atrium_document.schema.json`.
3. Extract text from the source representation using the decoupled extraction layer.
4. **Assembly check:**
   * If `--force-single-page` is active: concatenate all extracted text into a single page object sequence.
   * If default: map text blocks to their respective page/segment paths.
5. Mutate **only** the owned text blocks in the parsed document tree.
6. Verify preservation invariants for all non-owned fields.
7. Write the resulting updated JSON to disk.

## File-by-file changes

- **`extract_JSON_2_TXT.py`** — Major refactor. Split out the text extraction logic from the file output logic. Introduce the document mutation/accretion layer. Add CLI argument parsing for `--force-single-page`.
- **`setup/config.txt`** — Update configuration to reflect `doc.json` as both the expected input and output format. Document the new `--force-single-page` option.
- **`README.md`** — Overhaul documentation to explain the JSON-to-JSON workflow, the accretion model, schema ownership boundaries, and provide examples of normal usage vs. `--force-single-page`.
- **Tests to update/add (`tests/test_extract_json.py`)**:
  - `test_extraction_correctness`: Validates the decoupled extraction layer.
  - `test_accretion_preservation`: Ingests a fixture with mock metadata/paradata and asserts that non-owned fields remain untouched post-extraction.
  - `test_force_single_page`: Validates that multi-page inputs are deterministically concatenated into a single schema-valid page.
  - `test_schema_conformance`: Validates output against the canonical hub schema.

## Risks / open questions

| Risk                                      | Mitigation                                                                                                                                                                                                                                                                                    |
|-------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Literal "byte-identical" preservation     | Standard Python `json` module does not preserve bytes (whitespace/key order). If literal byte-for-byte is strictly required, investigate libraries like `ruamel.yaml` (in JSON mode) or `json5`. Otherwise, clarify with stakeholders that "semantic preservation" satisfies the requirement. |
| Accidental data loss during concatenation | Ensure `--force-single-page` has stable newline handling and deterministic ordering so paragraphs don't run together.                                                                                                                                                                         |

## Verification / done-criteria

- The script accepts an existing `doc.json` and produces an updated `doc.json`.
- Output successfully passes validation against the hub-canonical `atrium_document.schema.json`.
- Regression tests prove untouched parameters from the input JSON remain preserved.
- `--force-single-page` successfully forces multi-page structures into a single document page output.
- `README.md` and `setup/config.txt` reflect the new I/O behavior.
- Output can be directly consumed by `atrium-llm-enrich` without adapter scripts.
