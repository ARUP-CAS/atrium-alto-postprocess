## 🎯 Goal

The issue body is narrow: _“Proposed at the meeting - to be checked with tools/recategorize … make sure the new algo is aligned with the pipeline.”_ The PR-author clarification changes the scope reading slightly: this was meant to cover the corpus as a whole, with the 2010+ subset treated as the most important slice for the original request. Either way, the core task is verification of the categorisation pipeline, not a standalone feature request.

## 🔧 What changed

PR #32 merged seven commits into `test` and concentrated the change in `text_util.py` (+309/−5). The PR describes six independently reviewable logic changes plus a CodeQL fix:

- `2 → z` OCR repair no longer fires inside numbers.
- Neutral/reference tokens (dates, cites, initials, sigla, dotted abbreviations, units) are excluded from the valid-word ratio.
- Short lines with 1–2 words are routed through a structural gate instead of language confidence.
- A character-level damage detector caps damaged lines at `Noisy`.
- A clean-reference floor can lift some `Trash` lines to `Noisy`, but never the other way around.
- Extra fragment/bigram/case-mix/solitary-letter rules push obvious garbage to `Trash`.
- Overlapping abbreviation character ranges were cleaned up for CodeQL.

The PR’s own testing section says it used `tools/recategorize_from_csv.py` as the measurement instrument throughout, and it reports a sizeable improvement on its annotated samples. That means the issue’s literal ask was addressed through the same offline replay path it referenced.

## 🧭 What the current `test` branch docs say

The current `test` branch documentation now describes a richer scoring pipeline than the original issue text implied:

- `forgiven` is computed after the earlier gates, so it can only rescue lines that would otherwise fall to `Trash` late in the pipeline.
- Four late-stage penalty gates exist for rotated/wqx-heavy, vowelless, fragmented, and mid-uppercase lines.
- `check_rescues()` can still rescue some lines from `Trash` to `Noisy`.
- The main score band routing is still threshold-based, with `lm_confident_czech` and `rule_lowppl_clear` acting as important exceptions.
- `categorize_line()` clamps the stored `quality_score` to the band implied by the final label.
- `apply_document_postprocessing()` is still part of the production path, and the docs explicitly state it is reused by the offline re-scorer.

## ⚠️ What looks suspicious

The main concern is scope drift.

The issue is about keeping a new algorithm aligned with the pipeline, while the clarified intent says the change was meant for the corpus as a whole, with 2010+ as the most important subset. The merged PR still changed several independent rules at once. The current `test` branch docs also show that the scoring model has accumulated multiple late gates, rescue paths, and band-clamping behavior. That makes it harder to tell which specific change solved the issue versus which changes are policy choices.

Two parts deserve particular scrutiny:

- The short-line logic is a broad behavioral change, because archival records are full of short catalogue-style lines.
- The clean-reference floor and extra fragment rules are policy decisions, not just plumbing fixes.

Those changes may be justified, but they are wider than the issue title itself.
