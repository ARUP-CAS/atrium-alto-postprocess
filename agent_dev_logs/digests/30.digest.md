## 🔧 What resolved this issue — PR #32 (david-spacil, code by Claude Opus per its provenance note)
- Six commits to `text_util.py` (+309/−5): scoped the `2→z` OCR-repair regex out of numeric
  contexts; excluded reference/date/citation tokens from `compute_valid_ratio()`
  (`_is_neutral_token`); added a structural short-line gate for 1–2 word lines; added
  `count_damaged_tokens()` as a character-level damage cap; added `is_clean_reference()` as a
  Trash→Noisy floor; added stray-symbol/case-mix/fragment/bigram-run routes; fixed a CodeQL
  overlapping-character-range flag.
- **Measured exclusively through `tools/recategorize_from_csv.py`**, per the PR's own framing —
  directly satisfying this issue's ask. Three annotated samples (300-line uniform random,
  170-line complete-document, 654-line independent CTX collection) all show the same direction:
  61.3%→79.0% agreement with manual annotation on the primary sample (+17.7pp, McNemar
  p=5.2×10⁻⁹).
- Explicit, documented trade-off: recall on "needs attention" lines drops 72%→46% while
  precision rises 31%→50% — argued as the right call for a filter feeding clean text downstream,
  arguable as the wrong call for a manual-correction worklist. Left as K4TEL's call, not decided
  by the PR.
- Shipped with 8 known-failing tests (4 behavioral, 4 parity) and asked K4TEL to arbitrate
  rather than silently overriding them or hiding the trade-off.
- Merged into `test` as `f6adc23`, 2026-07-26.
