> **So the witness can no longer produce a new Clear-loss anywhere in its own population**, and the 41st does not belong to it.

**Where the 41st comes from, and why it is bigger than one line.** By elimination it is `apply_document_postprocessing()`'s modal dedup — the only branch that can move a line *out* of `Clear` (the other four require `categ == "Noisy"` or promote). It rewrites every row to the modal category of its identical text within a document, so convicting a few occurrences of a repeated string can flip the majority and carry a correct occurrence with it.

The consequence is the part worth keeping: **per-line precision does not bound Clear-loss.** The blast radius is the (document, string) group, not the line. The 20,078 lines sit behind **5,222 (document, string) pairs** — that many dedup votes — 44 groups of ≥20 lines cover 69.9% of the queue, and `ppole` alone is 22 votes controlling 11,562 lines. **This is not specific to the witness; any rule that convicts a repeated string inherits it.** Stage 5f (5a with `--no-postprocessing`) confirms or refutes the mechanism in one run; `classify_TEXT.py`'s dedup is deliberately unchanged until it reports.

**A second finding, and it was blocking an 87-hour job.** `tools/rule_coverage_report.py` did not produce a gold-scored `clear_loss` even when `--gold-column` was passed: `_loo_metrics` ran the gold pass, kept `gold_delta_macro_f1`, discarded the confusion matrix, and derived `clear_loss` from the *self-scored* pass. Against stored `categ` that column only counts lines the pipeline already called `Clear`, and at the shipped config the offline re-score reproduces those labels exactly — so it reads **0 by construction** however many readable lines a rule is really destroying. Demonstrated on a fixture where gold and stored disagree: `clear_loss = 0` while `gold_clear_loss = 2`. Fixed at zero extra passes, from the confusion already computed.

**And a correction to this document's own next-step 3.** It said every `DEAD` / `LOAD-BEARING` / `clear_loss` verdict "measured agreement with the pipeline's own output". Half right, and the halves matter:

- **`decisive_count`, and so `DEAD` / `REDUNDANT-HERE` / `LOAD-BEARING`, are self-scored and should be.** They measure how many lines a rule moves — a property of the rule, not a claim about truth. They never needed gold and were never wrong.
- **`clear_loss` is a correctness claim** and did need gold, which is the bug above.

The JSON's `decisive_scored_against` compounded it by reading `"gold"` on any `--gold-column` run — the one field that exists so a self-referential report can never be mistaken for a gold one.

## 🛑 Correction of 2026-09-19 — `ppole` is an abbreviation, and this document said otherwise

@david-spacil, [in thread](https://github.com/ufal/atrium-alto-postprocess/issues/30):

> *"`ppole` is not an OCR artefact (at least not every time), it's an abbreviation for urnfield
> culture, which also explains its frequency (and also the same position on pages with forms).
> Other examples of words with doubled first letter in `issue30_gold_ab_findings.md` truly are
> OCR artefacts."*

`pp` for *popelnicová pole* is a standard Czech doubling-for-plural abbreviation — the same
convention as `pp.` for pages or `ss.` for sections. **So `initial_geminate`'s stated premise,
*"no European orthography opens a word that way"*, is false for abbreviations** — and that is the
clause firing on 11,562 lines.

**What this reverses.** The 2026-09-17 block above argued the vocabulary veto was shielding a
conviction the clause got right. The clause got it **wrong**, and the veto was protecting real
vocabulary. The reading that block was written to correct was closer to the truth than the
correction. Logged as the **fourth inversion** in this issue, and the first that no internal
measurement could have produced: it needed someone who knows what the archive says.

Note the hedge — *"at least not every time"*. The abbreviation and genuine scanning doublings
occupy the same string, so `ppole` cannot be settled by a single label either, and the annotation
ask has to allow splitting it by context.

**What survives.** The other seven are confirmed artefacts on his own reading, so the
de-gemination guard is right on 7 of 8 and wrong on the one that matters most by volume.

**The separation is available, and it is not the ratio.** On the 822-document table:

| token                       | own df | base df |   ratio |
|-----------------------------|-------:|--------:|--------:|
| **`ppole`** — abbreviation  | **35** |     163 | **4.7** |
| `ssuti`                     |      8 |      42 |     5.2 |
| `ssutí` / `vvkop` / `ssutě` |    4–5 |   23–42 | 5.8–8.4 |
| `jjámy`                     |      5 |     356 |      71 |
| `oobjekt`                   |      3 |     378 |     126 |

`ppole` carries the **highest own frequency and the lowest ratio**; every confirmed artefact sits
at df ≤ 8. A scanning error appears in a handful of documents, an abbreviation in many. 4.7
against 5.2 is not a separation, but 35 against ≤ 8 is — so the fix is an **absolute cap on the
geminate's own document frequency**, not a higher ratio. To be re-checked on the

## 🔍 The vocabulary signal the pipeline already has, and does not use (2026-09-19)

`text_util.compute_valid_ratio(text, word_set=None)` takes a vocabulary and does a real lookup.
`classify_TEXT.py:245` calls it **without one**, so it falls back to shape: *≥3 characters, ≥70%
alphabetic, no odd characters → valid*. Measured:

```
compute_valid_ratio('oueussd edelite sektlll')  ->  1.00
```

**Pure garbage scores as 100% valid words.** `valid_word_ratio` feeds `compute_quality_score`,
which drives every threshold in this pipeline — so its primary *is-this-text* signal is
shape-only, and maximally fooled by the exact population issue #30 is about. With a word set the
same call returns `0.00`.

The hook is not a bolt-on; it is the parameter the function was written for, wired to nothing.
This is the largest available use of the collection lexicon, and also the largest change this
issue could make: it moves `quality_score` on every line in the corpus. It ships behind a flag,
off, and gets measured on gold first.

**One design constraint.** A strict word-set lookup scores `1 fraament okraie` at 0.00, but that
line is readable text. The word set must admit *attested OR one known transformation from
attested*, or `valid_word_ratio` punishes damaged-but-usable lines exactly as hard as garbage.

**A cheap gap alongside it.** `_STRIP_CHARS` is ``.,;:!?()[]"'\/`` — no symbol glyphs. So
`♦zkoumaná`, `✓stopy`, `•nevelká` enter the lexicon fused and the real word is unfindable at
lookup. Both ends of the same table are affected; the fix is one constant, and it changes
production tokenisation, so it is measured like everything else.

#### The second false-positive class, and the exemption that answers it

The roman numerals were the class the 508 exposed. The one below was named in the code, left
unmeasured for a month, and is larger.

The design block above `_has_shape_garbage_evidence()` recorded it as a known weakness and

| class                             | result                                                                                                                                                             |
|-----------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| botanical family names (`-aceae`) | **10 of 10 convicted** — `Poaceae`, `Rosaceae`, `Fabaceae`, `Brassicaceae`, `Cyperaceae`, `Chenopodiaceae`, `Asteraceae`, `Betulaceae`, `Fagaceae`, `Polygonaceae` |

`-aceae` is the botanical **family** suffix. The clause was therefore not making an occasional
mistake about a rare spelling; it was convicting the naming convention of a taxonomic rank, in
the collections whose archaeobotany reports are where that rank appears. Relying on `weird_ratio`

roman-numeral line the earlier exemption cleared still passes. Pinned by
`tests/test_shape_witness_vocabulary.py`.

them is the same guessing-by-reading that cost twelve lines the last time this predicate was
widened.

## 🚫 What this change is *not*

Two framings were tried and abandoned, and both are worth keeping on record because both survived review once.

**The symmetry argument does not hold.** The proposal was framed as "`rule_short_garbage` is the seventh sibling of six gated rules". Reading `50472fb`'s diff, it added `qs < thresh_trash` to sites that were *already* gated and never touched this rule. Those six live in §9, "explicit diagnostic hard gates" — late, weak, corroborating signals. `rule_short_garbage` sits in §6 among eight **early-exit** rules that all return unconditionally. It was never a guard that got skipped; it is a rule in the decisive family, which is a heavier burden, not a lighter one. The patch is not symmetric with those six anyway: they end in `check_rescues()`, this one returns `Trash` directly.

**"367,208 lifted / 0 demoted" is a theorem, not a measurement.** `determine_category` returns only `Empty`/`Trash`/`Noisy`/`Clear`, so removing an unconditional `return Trash` cannot demote anything. The direction was never in question. That figure is correct and carries **no evidence about whether the change is right** — only §3.2 does.

### Out of reach by construction — needs a lexicon, and now has one

`edelite`, `vfetennl k.`, `Slaot-o hiezazzt`. Phonotactically legal, so only word knowledge separates them from real vocabulary. Asserted as **part of the contract** in `test_the_disjunction_the_gate_will_evaluate_separates_the_population`, rather than quietly omitted — a lexicon-free approach has to own this residue, not pretend it away.

The honest form of the long-running claim is therefore: separating `malakofauna` from **`edelite`** needs a lexicon. Separating `malakofauna` from **`oueussd`** does not — that was the blocking claim for three rounds and it is false.

**2026-09-17 — the lexicon exists (D14).** Not an external dictionary: the Czech ones are
CC BY-NC-SA and the clause would follow this pipeline's output, and a Latin binomial list would
cover `Equus caballus` while missing `Reg.Bez.Aussig.` — and none of them contains the site codes,
context labels and excavation shorthand that make up most of this corpus's short lines.

The corpus is its own dictionary, and it was already on disk:

> A token that appears in many **distinct documents** is vocabulary.
> A token that appears in one is what that scan did to some ink.

**Document** frequency, not line frequency — OCR noise repeats freely inside the scan that
produced it, the same misread header on forty pages, and almost never across scans made years
apart by different operators. Counting lines would let one badly-scanned document vote its own
garbage into the dictionary. And it is a property of the **data**, not of the classifier: nothing
in the builder reads `categ` or `quality_score`, which matters because this issue has already
built one circular objective and a lexicon filtered by "lines we called `Clear`" would be the
same mistake wearing a different hat.

It is used two ways, and they are gated separately because they carry different risk:

| use                                       | what it does                                                                                                                                                                 | ships                                                   |
|-------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------|
| **veto** — `_has_vocabulary_support()`    | an attested token cannot be convicted. Exemption-only, so it can never add a `Trash` verdict. Reaches `Naiade`, `Beuern`, `Oueste`                                           | inert unless `SHORT_GARBAGE_LEXICON_PATH` names a table |
| **evidence** — the `no_vocabulary` clause | an **un**attested token convicts. The only mechanism in the module that reaches `edelite` and `vfetennl k.` — and the only clause of the witness that can *add* a conviction | `SHORT_GARBAGE_LEXICON_CONVICT`, its own key, `false`   |

The second is where the caution belongs: **"unattested" is not "not a word".** A genuinely rare
term, a personal name, or a table built too narrowly all land in the same bucket as the residue.

#### Measured, 2026-09-17 — the hypothesis holds, the threshold does not

@K4TEL built the table on the cluster: **822 documents, 12,716,706 lines, 347,097 distinct
tokens** at `min_alpha 4`, of which 54,462 (15.7%) reach df ≥ 3. Scored through the real
predicate:

|                            | vocabulary wrongly convicted (of 31 pinned fixtures) | named garbage not convicted (of 10)  |
|----------------------------|------------------------------------------------------|--------------------------------------|
| shipped default — no table | 0                                                    | 3 — `edelite`, `vfetennl k.`, `olie` |
| + veto, `min_df` 3         | 0                                                    | **4** — the above plus `cuxoaid`     |
| + conviction, `min_df` 3   | **5**                                                | 2                                    |

**The mechanism works and the setting is wrong.** Three separate readings:

* **Document frequency does separate the two populations.** `vrstva` 429, `kontext` 216,
  `malakofauna` 63, `quercus` 55, `corylus` 45, `equus` 44 / `caballus` 38, `maxilla` 33,
  `occipitale` 23 — against `oueussd` 1, `sektlll` 1, `rragment` 1, `ninnnic` 1, `edelite` 1,
  `vansasaasasa` 0, `tthts` 0, `vfetennl` 0. The residue **is** reached: turning the clause on
  convicts `edelite` and `vfetennl k.`, which nothing in this module could do before.
* **The botanical class is attested independently** — `poaceae` 23, `rosaceae` 5, `fabaceae` 4 —
  so the veto would have protected R1's class on its own. Two mechanisms agreeing from different
  directions is worth more than either.
* **At `min_df` 3 it breaks five of the 31 pinned vocabulary fixtures**: `Pinii`,
  `Uniocrassus`, `Aachen`, `Hannah`, `Emma`, and `Skelettmaterial` (df 2) outside that list.
  Personal names, place names and a rare taxon — precisely the failure the code comment
  predicted, arriving on schedule. In the other direction the veto **protects** `cuxoaid` (df 4)
  and `olie` (df 4), this repository's own canonical short-garbage example.

`SHORT_GARBAGE_LEXICON_CONVICT` therefore **stays false**, on evidence rather than on caution.
And the fix is probably not to tune `min_df` on this table: 822 of 113,101 documents is 0.7% of
the collections, so `Skelettmaterial` at 2 and `Pinii` at 1 are thin-corpus artefacts as much as
they are rare words. **Rebuild over both full collections before touching the threshold** — the
same command, and still no GPU.

One number to carry into that decision: **74.3% of distinct tokens are hapax** (seen in exactly
one document), 10.0% appear in two. The conviction clause fires on absence, so its reach at the
type level is three-quarters of the vocabulary of this corpus. That is not three-quarters of
*lines* — common words dominate lines — but it is the right order of magnitude to be frightened
of, and it is why this clause has its own key.

Built with `tools/build_token_lexicon.py` (CPU-only, no model, no GPU), which imports its
tokenisation from `text_util` rather than copying it — a table keyed differently from the way the
predicate looks tokens up would miss every lookup, and a missed lookup reads as "no vocabulary
support", i.e. as a witness that convicts *more*. That is the direction that costs real lines, and
nothing in the output would say so. Four harness divergences in this repository came from a copied
implementation (§5); this one is pinned by a test that compares the two paths token for token.

### Structural facts that constrain any future fix

- **No perplexity rule can fire at `wc ≤ 2`.** `SHORT_PPL_CAP` (850) < `HARD_SWEEP_PPL_MIN` (1,000) < `PPL_EXTREME_MIN` (3,000) < `PPL_GARBAGE_ABSOLUTE` (30,000). Perplexity is structurally unable to intervene at any value.
- **Section 7 (`rule_short_line`, `text_util.py:1380-1439`) is total for `wc ≤ 2`.** Every branch returns, so §8–§10 and `check_rescues()` are unreachable for that population. Its `damage` branch returns **`Noisy`, never `Trash`** (`text_util.py:1424-1425`) — which is why a witness placed there could never restore a `Trash` verdict.
- **`check_rescues()` (`text_util.py:1462`) cannot supply a `Noisy` floor.** All three of its floors — `_trailing_fill_rescued()`, `is_forgiven_headline()`, `is_clean_reference()` — evaluate `False` on all 11 lines tested, so it returns `Trash` for every one, `malakofauna` and `1 ks` included. Routing gate 6 through it buys symmetry and changes nothing.
- **`compute_valid_ratio()` (`text_util.py:2405`) is shape-only** — a token counts as valid on length ≥ 3, ≥ 70% alphabetic, no strange character, no mid-word uppercase. So `valid_word_ratio == 1.0` for this entire population, `oueussd` included. This is the suppression at the heart of the issue: section 7 already reads the discriminating witness inside its `damage` term and then vetoes it with `structurally_clean = valid_word_ratio >= 1.0`.
- **`rule_mid_uppercase` is unreachable**, shadowed by gate 7's identical `word_count <= 2` condition. Recorded in `UNREACHABLE_RULES` and pinned by `test_mid_uppercase_is_shadowed_by_short_line`.
- **Dot-chains still reach `Clear`** — periods collapse a line to `wc == 1`, the cap flattens perplexity, and gate 7 reads `valid_word_ratio >= 1.0` because `.` is in `ALLOWED_INTERNAL`. Same root cause as #30; deserves its own issue.
- **`service/text_api.py` double-imports its own app** — `uvicorn.run("text_api:app", ...)` re-runs the module body under a second name, so `app` / `_state` / `TextModelManager()` exist twice and the served `_state` is not the one `__main__` holds. Unrelated to #30; deserves its own issue.

### Harness divergence — the recurring failure mode

Three separate harnesses in this repository have fed `categorize_line` a value production never computes, and each produced confident wrong numbers before it was caught:

1. `tests/test_rotation_regression.py` fed the `LANG_SCORE_REMAP` cap (0.75) where production feeds the trust score (0.9163 on the `oueussd` fixture) — every assertion in the module was about a value that does not exist.
2. `_categ` / `_process_mocked_line` hardcoded `original_lang="ces_Latn"`, granting trust tier 1.0 where production applies `TRUST_TIER_UNKNOWN` (0.50). This is what made `Equus caballus` and `diapozitiv` look "green on master, therefore non-discriminating" — scored properly, all three are `Trash` and all three discriminate.
3. `tests/test_smoke.py` carried the same bug a third time, and additionally omitted `orig_lang_score` and `garbage_density`, leaving them at `1.0` / `0.0` and silently disabling `rule_hard_sweep`, `rule_extreme_ppl` and the density branch of `_has_strong_garbage_evidence`.

All three are fixed; `test_smoke.py` now routes through `_rescore_row`. `tools/short_garbage_witness_report.py` was described here as text-only *by construction* and therefore immune — and then produced the fourth instance anyway.

**4. `tools/short_garbage_witness_report.py` carried its own copy of the witness clauses.** It re-implemented all four so it could name which one fired, guarded by an assertion in `classify_line` that its diagnosis matched the predicate. The roman-numeral exemption (2026-09-10) landed in the predicate and not in the copy. The guard did exactly what it was written to do — it fired — on **0.74% of real lines**, which is every line carrying a roman numeral: `XVIII. '`, `23. VIII.1947.`, `580. Hr. VIII.4.`. The tool aborts on the first, so it was unusable on real data for precisely the exposure measurement the flag decision is gated on.

Fixed structurally rather than by patching the copy: `text_util.shape_garbage_clauses()` is now the single implementation, `_has_shape_garbage_evidence()` is `bool()` of it, and the report imports both the vocabulary and the logic. Verified over the full 367,208-line delivery: **0 crashes**. `tests/test_short_garbage_witness_report.py` gained the roman-numeral corpus and a test that fails if a local clause implementation reappears.

The lesson is the one this section already taught, with a sharper edge: *"text-only by construction"* was true and irrelevant. The bug was duplication, not signal reconstruction, and the guard caught it only because someone wrote the guard. The discipline is what prevents a fifth.

**5. The instrument that classifies the rules was scoring against itself** (2026-09-17, R1–R3 block). Not a harness fed a wrong value — a harness fed the *right* value and asked the wrong question. `rule_coverage_report._loo_metrics` never passed `gold_category_column`, so every `DEAD` / `REDUNDANT-HERE` / `LOAD-BEARING` / `clear_loss` figure was measured against the pipeline's own stored `categ`, which the offline re-score reproduces exactly — a baseline of zero, by construction.

It belongs in this section because the shape is identical: **the run completes, prints a full and plausible table, and is worth nothing.** The same file accepted `--gold-sidecar`, joined it, and printed "N labels matched" on the way past, so a gold run and a self-scored run were indistinguishable from the output. `tests/test_rule_coverage.py` contained no occurrence of the word `gold`.

Fixed with the same structural instinct as #4: the gold verdict is *added* beside the structural figures rather than substituted for them (forwarding the keyword would have redefined `decisive_count`, since `flip_count` counts disagreements-with-gold once a gold column is present), the JSON payload now records `gold_column` and `decisive_scored_against`, and a source-level test asserts across **all five** `evaluate_dataframe` callers that none of them can drop the keyword again.

A sixth of the same family, found in the same round and worth recording because it is the cheapest to repeat: pointing a recursive driver at `tools/gold/` swept the 2,067-row sidecar in as corpus lines and reported **2,082 lines instead of 15**, with a complete table and no error. `GOLD.md` had warned about it in prose since the sidecar arrived; `load_csvs` now skips CSVs with no `text` column and says so.
