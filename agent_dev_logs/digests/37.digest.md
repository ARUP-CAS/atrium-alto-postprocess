# 📓 Digest — [\#37](https://github.com/ufal/atrium-alto-postprocess/issues/37) `open`: JSON-2-TXT breaks downstream architectural contract

**Labels**: `development`, `integration`, `bug`, `testing`
**Status**: 🟡 Planned — opened recently; design work and accretion semantics resolved offline (this session) and captured in `../plans/37.plan.md`. A recent comment added requirements for E2E subprocess testing. No production code changed.

## 🎯 Goal & Core Constraint
Refactor the draft JSON-2-TXT extractor introduced in `v1.2.1-beta` so it aligns with the `atrium_document.schema.json` paradata-pair accretion model. It must transition from a raw plain-text output script to a JSON-to-JSON mutation tool. It must ingest `doc.json`, update exactly its owned text structures, preserve all unrelated metadata, and correctly implement the missing `--force-single-page` CLI flag. Additionally, the CLI execution path must be validated via end-to-end (E2E) subprocess testing.

## 🏆 Headline Findings & Conclusions

**1. This is a contract migration, not just a script rewrite.**
The core failure is an architectural mismatch with downstream consumers like `atrium-llm-enrich`. The solution requires defining strict JSON ownership boundaries before changing the extraction logic. We must map extracted text explicitly to the document/page/text structures defined by the canonical schema.

**2. Extraction and mutation must be decoupled.**
Embedding document mutation logic directly inside the extraction loop is risky and hard to test. The architecture will be split into an Extraction Layer (yielding an intermediate text representation) and an Accretion Layer (handling the safe mapping and merging into `doc.json`).

**3. The "byte-identical" requirement needs strict enforcement.**
A naive `json.loads()` and `json.dumps()` round-trip will destroy original JSON formatting (whitespace, key order) of untouched fields. The implementation must guarantee that unrelated metadata (like existing paradata or custom IDs) remains entirely unmutated, either by using a format-preserving JSON library or by enforcing strict semantic equality in the validation phase.

**4. `--force-single-page` is a document assembly policy.**
This flag should not tangle the text extraction rules. Instead, it will act as a policy switch at the document assembly layer: taking segmented or multi-page output and deterministically concatenating it into a single schema-valid page representation, while leaving the rest of the document intact.

**5. E2E subprocess testing is required to guarantee CLI stability.**
Unit tests alone mask potential failures in argument parsing, file I/O, and environmental constraints. A dedicated subprocess test suite is required to simulate real-world CLI execution (specifically testing the `--method json-keys` approach) and verify integration robustness.

## 🏁 Final Bottom Line
Planning is complete and captured in `agent_dev_logs/plans/37.plan.md`. The highest-risk element remains the accretion contract and metadata preservation. Implementation will begin by establishing regression fixtures, decoupling the extraction logic, and writing the new E2E subprocess tests to validate the native/containerized CLI execution flow.
